# Our Chapter · 우리의 결혼 준비

송윤오 ♥ 박예은의 결혼 준비를 위한 아이보리·올리브 테마의 한국어 개인 웨딩 플래너. React + Vite 기반으로 데스크톱과 모바일을 지원합니다.

## 실행
Node.js 22 이상 권장. 현재 환경에서는 Node.js 24.19.0으로 검증합니다.

```sh
npm ci
npm run dev
```

개발 서버는 기본 5173 포트를 사용합니다.

```sh
npm test
npm run build
npm run preview
```

## 기능
- 발리 신혼여행: 날짜별 일정·항공/숙소 예약·여행 준비물·원화 예산 관리
- 커플 이름, 결혼 날짜, 총 예산 설정
- 신혼집 꾸미기: 방별 가구·가전·소품, 치수·스타일·상품 링크·배송 상태 관리
- 할 일 추가·완료·삭제 및 완료 필터
- 항목별 계획·계약 금액, 계약금·잔금 결제 내역, 분류별 집계 및 예산 초과 표시
- 하객 추가·삭제 및 참석 상태 변경
- 준비 날짜별 일정과 결혼식 카운트다운
- 더파티움 안양 5층 브리에홀 소개·공식 사진·오시는 길·주차 안내
- JSON 데이터 백업·복원

현재 게시 사이트는 Supabase의 서버 인증과 공유 데이터베이스를 사용합니다. 관리자 변경 사항은 다른 접속자에게 실시간으로 전달됩니다. 프로젝트 설정이 없는 개발 환경에서는 해당 브라우저의 localStorage를 사용하며 시작용 할 일 예시를 표시합니다. 관리자는 하단의 백업 버튼으로 기록을 보관할 수 있습니다.

디자인 방향과 레퍼런스는 [DESIGN.md](DESIGN.md)에 기록했습니다. 네트워크 제한으로 최신 레퍼런스 화면은 직접 확인하지 못했습니다.

## 상세 결혼 예산 관리

‘예산 관리’에서 계획 금액과 계약·확정 금액을 따로 입력하고, 각 항목의 계약금·중도금·잔금을 결제일·결제수단·부담자와 함께 기록합니다. 항목과 개별 결제 내역은 수정·삭제할 수 있습니다. 미확정 항목은 계획 금액으로 예상 총비용에 포함하고, 남은 잔금은 확정 금액에서 결제 완료액을 뺀 값으로 표시합니다. 대시보드에도 예상 비용과 실제 지급액을 구분합니다.

13개 기본 분류와 직접 입력한 분류를 지원합니다. 필요한 기본 항목만 선택해 불러오거나, 단가 × 수량으로 식대·답례품 등의 계획액을 계산할 수 있습니다. 검색·분류·결제 상태·정렬, 기한이 지난 잔금 표시, 월별 결제 내역 조회, 항목표·결제 내역 CSV 다운로드를 제공합니다. 관리자만 변경·내보내기를 할 수 있고 게스트는 읽기·조회만 할 수 있습니다.

기존 지출은 원래 금액 그대로 결제 완료 기록으로 표시하며, 날짜를 추정해서 채우지 않습니다. 상세 금액을 저장할 때 기존 결제 기록을 보존합니다. 신규 상세 항목과 결제는 기존 공유 JSON 안에 저장하므로 운영 데이터베이스 스키마 변경이 필요하지 않습니다. JSON 백업·복원도 두 형식을 모두 지원합니다.

참고: [Vertex42 결혼 예산표](https://www.vertex42.com/ExcelTemplates/wedding-budget.html)의 계획·실제 비용 비교, [YNAB](https://www.ynab.com/guide/where-does-my-money-go)의 항목별 배분, [The Knot](https://www.theknot.com/content/wedding-budget-ways-to-save-money)의 결혼 비용 분류. 양식 파일을 복제하거나 해외 비율·금액을 실제 예산에 자동 적용하지 않습니다.

## 발리 신혼여행

‘신혼여행’ 메뉴에서 여행 날짜와 별도 예산을 정하고, 항공·숙소·체험·이동·식사 예약을 등록합니다. 날짜와 시간순의 여행 일정, 아직 날짜를 정하지 않은 계획, 지역별 예약·준비 상태를 조회하고 업체·예약 링크·메모·계획/확정 비용을 수정할 수 있습니다. 금액은 원화(KRW)로 입력합니다. 준비물은 직접 추가하거나 필요한 기본 준비물만 골라서 추가하세요. 기본 예약 항목도 선택해서 불러오며 실제 날짜·가격·예약 상태는 사용자가 입력합니다.

‘예산에 연결’로 원하는 항목을 전체 결혼 예산에 포함하고 ‘예산 반영’으로 수정한 금액을 갱신합니다. 반복 연결은 중복을 만들지 않고, 기존 결제 내역은 유지하며 실제 결제는 예산 관리에서 기록합니다. 일정·준비물은 기존 공유 JSON의 선택 `honeymoon` 필드에 저장하고 이전 백업도 계속 지원합니다. 게스트는 읽기 전용으로 조회합니다.

지역 안내는 [인도네시아 공식 관광 사이트](https://www.indonesia.travel/)의 우붓·울루와투·누사두아·스미냑 자료를 확인해 작성했으며, 안내 카드에서 각 공식 자료로 이동할 수 있습니다.

## 신혼집 꾸미기

기본 공간은 거실·안방·큰방·작은방·화장실·세탁실·베란다입니다. ‘공간 관리’에서 품목이 없는 공간도 추가하고 이름을 바꿀 수 있으며, 이름 변경 시 기존 품목도 함께 이동합니다. 기존 침실·욕실·서재·세탁 품목은 새 공간명으로 정리하고 주방·현관 등 추가 공간은 보존합니다. 금액·결제 기록·구매 정보는 유지하고 기본 품목을 다시 불러와도 중복되지 않습니다.

‘신혼집 꾸미기’ 메뉴에서 공간별 가구·가전·조명·패브릭·수납·소품을 정리합니다. 품목의 치수(cm), 색상·소재·배치 위치, 수량과 계획·실구매 단가, 상품 링크, 배송·설치 예정일과 메모를 기록하고 수정할 수 있습니다. 공간·분류·상태 필터와 검색으로 필요한 항목을 찾아보세요. 기본 품목은 직접 선택해 추가하며 가격은 입력한 값으로 계산합니다.

꾸미기 예산은 별도로 설정합니다. 전체 결혼 예산에 포함할 품목은 ‘예산에 연결’을 선택하세요. 연결 이후에는 ‘예산 반영’으로 수정한 품목의 금액을 반영하고 ‘예산에서 보기’로 결제 내역을 관리합니다. 같은 품목을 반복 연결해도 예산 항목이 중복되지 않으며, 실제 지급액은 예산 화면에서 기록합니다. 꾸미기 목록에서 품목을 삭제해도 기존 결제 내역이 있는 예산 기록은 보존합니다.

새 데이터는 기존 공유 JSON의 `home` 필드로 저장합니다. 이 필드가 없는 이전 기록·백업도 계속 읽을 수 있습니다. 관리자만 추가·수정·삭제·예산 연결을 사용하고, 게스트는 목록 조회·필터·상품 링크 열기를 사용할 수 있습니다.

## 웨딩홀 소개

‘웨딩홀 소개’ 메뉴와 대시보드의 웨딩홀 카드에서 **더파티움 안양 5층 브리에홀**을 확인할 수 있습니다. 어두운 홀의 샹들리에·생화 장식과 실제 신부대기실 사진, 주소·전화번호, 평촌역 교통편과 주차장 안내를 제공합니다. 일정 화면에도 동일한 예식 장소를 표시합니다. 관리자와 게스트 모두 소개와 지도·전화·주소 복사를 사용할 수 있습니다.

소개 정보는 `app/src/venue.js`, 화면은 `app/src/Venue.jsx`에서 관리합니다. 공식 사진은 로컬 WebP 에셋으로 포함하며, 출처와 확인일은 [사진 출처](app/src/assets/venue/SOURCES.md)에 기록했습니다. 기존 영감 즐겨찾기 UI는 제거했고, 과거 백업·공유 기록의 `saved` 필드는 호환성을 위해 보존합니다.

## 브라우저 검증
```sh
npx playwright install chromium
npx playwright test
```

브라우저 검사는 별도 테스트 서버와 빈 연결 설정을 사용해 기존 브라우저 저장 기능을 검사합니다. 운영 Supabase에 기록하거나 인증 메일을 보내지 않습니다. 테스트 서버는 자동으로 시작되므로 `npx playwright test` 실행 전에 개발 서버를 띄울 필요가 없습니다.

클라우드 환경에 설치된 Chromium을 사용할 때는 다음 명령을 실행하세요.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npx playwright test
```

## GitHub Pages 배포

현재 설정: **Settings → Pages → Deploy from a branch → main / (root)**.

`app/`에 개발 소스가 있고, 저장소 루트의 `index.html`, `assets/`, `.nojekyll`은 Pages용 빌드 결과입니다. `npm run build`는 Vite로 빌드한 뒤 루트 게시 파일을 갱신합니다. 기능을 수정할 때 소스와 갱신된 게시 파일을 함께 커밋·푸시하세요. 이전 빌드의 에셋은 `.pages-manifest.json`에 기록된 파일만 정리합니다.

게시 주소: https://devuknow.github.io/Ethan_Wedding_Planning/

상대 에셋 경로를 사용해 저장소 하위 경로에서도 JavaScript와 CSS가 로드됩니다. `.github/workflows/ci.yml`은 테스트와 빌드 후 커밋된 게시 파일이 최신인지 검사합니다. 실제 게시 작업은 기존 GitHub Pages 브랜치 설정에서 수행됩니다.

## 접속 화면과 역할

첫 접속 시 이름·별명·관리자 이메일을 입력하거나 **게스트로 보기**를 선택합니다. 관리자는 지정된 이름·별명 확인과 등록된 이메일의 인증을 마친 뒤 편집·추가·삭제·설정·백업·복원을 사용할 수 있습니다. 현재 서버에 등록된 관리자는 송윤오 한 명이며, 박예은은 이메일 등록 후 관리자 인증을 사용할 수 있습니다. 게스트는 화면을 둘러보고 필터를 사용할 수 있지만 할 일 완료·삭제, 참석 상태 변경, 설정 변경, 데이터 복원은 사용할 수 없습니다.

상단의 나가기 아이콘으로 접속 화면으로 돌아갈 수 있습니다. 게스트 역할은 현재 탭의 sessionStorage에 보관하며, 연결된 관리자는 새로고침 시 Supabase 인증 세션과 서버의 이메일 허용 목록으로 권한을 다시 확인합니다. 별명 입력값은 저장하지 않습니다. 준비 내역은 역할 전환으로 삭제되지 않습니다.

프로젝트 미연결 상태의 이름·별명 입장은 정적 사이트의 **화면 권한 구분**이며 보안 인증이 아닙니다. 관리자 이름·별명 비교는 공개된 프런트엔드에서 이루어지므로 개발자 도구로 우회할 수 있습니다. Supabase 연결 후에는 서버의 관리자 이메일 허용 목록으로 쓰기 권한을 검증하고, 게스트도 공용 데이터를 봅니다. 연결 전에는 게스트에게도 현재 브라우저의 기록만 표시합니다.

## 기기 간 동기화

Supabase 연결 시 이메일 인증을 거친 관리자만 서버에 저장하고, 게스트는 공유 기록을 읽기 전용으로 봅니다. 변경 사항은 실시간 구독으로 다른 기기에 반영하며 revision 비교로 동시 수정 충돌을 처리합니다.

`app/cloud-config.json`에 Project URL과 공개 publishable 키를 설정했습니다. 운영 프로젝트에서 사용자에 의한 관리자 이메일 인증·수정과 서버 저장을 확인했고, 두 개의 독립 게스트 연결이 동일한 실시간 변경을 받는 것도 검증했습니다. 새 프로젝트를 연결할 때 필요한 설정과 검증 절차는 [SYNC_SETUP.md](SYNC_SETUP.md)에 설명합니다. 실제 관리자 이메일과 SMTP 비밀번호는 공개 저장소에 기록하지 않습니다. 서버 기록을 읽을 수 없으면 연결 오류를 표시하고 저장을 진행하지 않습니다.
